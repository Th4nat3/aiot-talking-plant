🌿 AIoT Eco-Companion: Talking Plant

สื่อการเรียนรู้ระบบเอไอโอที (AIoT) การเชื่อมต่อกายภาพสู่ประมวลผลทางภาษาด้วย Generative AI

กลุ่มเป้าหมายของสื่อการเรียนรู้นี้ (Target Audience)

สื่อการเรียนรู้นี้ถูกออกแบบโครงสร้างเนื้อหาและการทดลองมาโดยเฉพาะสำหรับ:

  • นักเรียนระดับมัธยมศึกษาตอนปลาย (สายวิทยาศาสตร์-เทคโนโลยี / คอมพิวเตอร์): ที่ต้องการเรียนรู้พื้นฐาน Microcontroller และ IoT
  • นักเรียนระดับ ปวช. / ปวส. สาขาช่างอิเล็กทรอนิกส์และเทคโนโลยีสารสนเทศ: ที่ต้องการต่อยอดงานฮาร์ดแวร์สู่ระบบ AI
  • นักศึกษาปริญญาตรีชั้นปีที่ 1-2 (สาขาวิศกรรมคอมพิวเตอร์ / IT / Data Science): ที่เริ่มต้นศึกษาการทำ System Integration ร่วมกับ Cloud LLM APIs

แนวคิดหลักของโปรเจกต์ (Project Core Concept)

ในระบบ IoT แบบดั้งเดิม เซ็นเซอร์ทำหน้าที่ส่งเพียงค่าตัวเลข เช่น 34°C หรือ Soil Moisture 20% ซึ่งผู้ใช้อาจไม่เข้าใจว่าพืชกำลังตกอยู่ในสภาวะวิกฤตหรือไม่

โปรเจกต์ "Talking Plant" จึงนำแนวคิด AIoT (AI + IoT) มาแก้ปัญหานี้ โดยใช้บอร์ด ESP32-S2 (Cucumber RS) อ่านค่าเซ็นเซอร์สภาพแวดล้อม ส่งผ่านโปรโตคอล MQTT ไปยัง Cloud Server ที่รันโมเดลภาษาขนาดใหญ่ Groq AI (LLaMA 3.3 70B) เพื่อแปลงข้อมูลตัวเลขให้กลายเป็น "บทพูดขี้อ้อนที่มีบุคลิกเหมือนสิ่งมีชีวิต" และแจ้งเตือนผ่าน Telegram Bot แบบเรียลไทม์

วัตถุประสงค์เชิงพฤติกรรม (Learning Outcomes)

1. ด้าน Hardware & Sensing
เข้าใจการต่อวงจร I2C Bus และการอ่านค่าอนาล็อกผ่านขาสัญญาณ ADC1 บนชิป ESP32-S2
2. ด้าน IoT Networking
เข้าใจโครงสร้างสื่อสารข้อมูลแบบ Publish/Subscribe และ JSON Payload บน MQTT Protocol
3. ด้าน Cloud & Generative AI
สามารถออกแบบ Prompt Engineering (System Prompt) เพื่อควบคุมบุคลิกและเงื่อนไขการตอบของ LLM

สถาปัตยกรรมระบบ 4 ชั้น (4-Tier AIoT Architecture)

การทำงานของระบบแบ่งออกเป็น 4 ลำดับขั้นหลักตามมาตรฐานการออกแบบระบบ AIoT ระดับสากล:

1. Edge Perception

บอร์ด ESP32 อ่านค่าจากเซ็นเซอร์ HTS221 (I2C) และ เซ็นเซอร์วัดความชื้นในดิน (ADC1)

2. Data Transport

แปลงค่าเป็นข้อความ JSON แล้วส่งเข้า Public MQTT Broker (broker.hivemq.com)

3. Cognitive Processing

Google Colab ดึงข้อมูล MQTT และส่งคำร้องขอ HTTP POST ไปประมวลผลบทพูดด้วย Groq AI (LLaMA 3.3)

4. User Interaction

ส่งข้อความภาษาไทยที่มีความรู้สึกเข้า Telegram Bot ของผู้ใช้งาน พร้อมระบบ Cooldown กันข้อความรัว

โครงสร้างแพ็กเกจข้อมูล (MQTT JSON Data Structure)

ข้อมูลที่ ESP32 จัดส่งผ่าน MQTT Topic /plant/status มีโครงสร้างมาตรฐานดังนี้:

{
  "temperature": 34,
  "humidity": 50,
  "soil_moisture": 92,
  "plant_name": "น้องมอนสเตอร่า"
}

ผังการต่อขาสัญญาณบอร์ด Cucumber RS (ESP32-S2)

บอร์ด Cucumber RS ใช้ชิปประมวลผล ESP32-S2 ซึ่งตำแหน่งขาสัญญาณ I2C Onboard และกลุ่มขา ADC1 มีข้อกำหนดเฉพาะดังตาราง:

อุปกรณ์ / เซ็นเซอร์ พินบนตัวเซ็นเซอร์ ขาบนบอร์ด ESP32-S2 ประเภทสัญญาณ คำอธิบายทางเทคนิค
HTS221 Sensor SDA GPIO 41 Digital I2C Data สายส่งข้อมูล I2C ของบอร์ด Cucumber RS
HTS221 Sensor SCL GPIO 40 Digital I2C Clock สายสัญญาณนาฬิกา I2C (ระบุใน Wire.begin(41, 40))
Soil Moisture Sensor AOUT (Analog Out) GPIO 1 Analog Input (ADC1) ย้ายจาก GPIO 34 มาใช้ GPIO 1 เพราะเป็นกลุ่มขา ADC1 ที่รองรับอ่านค่าอนาล็อก
VCC & GND VCC / GND 3V3 / GND Power Supply ระบบจ่ายไฟเลี้ยงแรงดัน 3.3V ให้เซ็นเซอร์

ข้อควรระวังและการแก้ปัญหาฮาร์ดแวร์ (Troubleshooting)

  • ข้อผิดพลาด Pin 34 is not ADC pin!: เกิดจากการใช้ขา GPIO 34 บน ESP32-S2 ซึ่งไม่ใช่พินอ่านอนาล็อก ให้เปลี่ยนไปใช้ขา GPIO 1 ถึง 14 แทน
  • ข้อผิดพลาด Wire.cpp Error -1: เกิดจากบอร์ดหากับเซ็นเซอร์ I2C ไม่เจอ ต้องระบุคำสั่ง Wire.begin(41, 40); ในฟังก์ชัน setup() ก่อนเรียกใช้งานเซ็นเซอร์ HTS221

1. โค้ดฝั่ง ESP32 Firmware (PlatformIO - src/main.cpp)

โค้ดสมบูรณ์ภาษา C++ สำหรับเขียนลงบอร์ด ESP32-S2 เพื่ออ่านค่าเซ็นเซอร์และส่ง MQTT:

#include <Arduino.h>
#include <Wire.h>
#include <Adafruit_HTS221.h>
#include <WiFi.h>
#include <PubSubClient.h>
#include <ArduinoJson.h>

// --- ตั้งค่า Wi-Fi และ MQTT Broker ---
const char* ssid = "ArtitInwzaa";
const char* password = "Artitnakrap";
const char* mqtt_server = "broker.hivemq.com";
const int mqtt_port = 1883;
const char* mqtt_topic = "/plant/status";

// กำหนดขาเซ็นเซอร์ความชื้นดิน (ใช้ขา ADC1 เช่น GPIO 1)
#define SOIL_PIN 1 

Adafruit_HTS221 hts;
WiFiClient espClient;
PubSubClient client(espClient);
unsigned long lastMsg = 0;

void setup_wifi() {
  delay(10);
  Serial.println("\nConnecting to WiFi...");
  WiFi.begin(ssid, password);
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
  Serial.println("\nWiFi connected! IP: " + WiFi.localIP().toString());
}

void reconnect() {
  while (!client.connected()) {
    Serial.print("Attempting MQTT connection...");
    if (client.connect("ESP32_TalkingPlant_Client")) {
      Serial.println("connected");
    } else {
      Serial.print("failed, rc=");
      Serial.print(client.state());
      Serial.println(" try again in 5 seconds");
      delay(5000);
    }
  }
}

void setup() {
  Serial.begin(115200);
  
  // กำหนดขา I2C สำหรับบอร์ด Cucumber RS (SDA=41, SCL=40)
  Wire.begin(41, 40); 

  if (!hts.begin_I2C()) {
    Serial.println("Failed to find HTS221 chip!");
  } else {
    Serial.println("HTS221 Initialized!");
  }

  setup_wifi();
  client.setServer(mqtt_server, mqtt_port);
}

void loop() {
  if (!client.connected()) {
    reconnect();
  }
  client.loop();

  unsigned long now = millis();
  // ส่งข้อมูลเข้า MQTT ทุกๆ 10 วินาที
  if (now - lastMsg > 10000) { 
    lastMsg = now;

    sensors_event_t temp, hum;
    hts.getEvent(&hum, &temp);

    int soilRaw = analogRead(SOIL_PIN);
    // แปลงค่าสัญญานอนาล็อกเป็นเปอร์เซ็นต์ความชื้นดิน (0-100%)
    int soilMoisture = map(soilRaw, 4095, 0, 0, 100); 
    soilMoisture = constrain(soilMoisture, 0, 100);

    StaticJsonDocument<200> doc;
    doc["temperature"] = (int)temp.temperature;
    doc["humidity"] = (int)hum.relative_humidity;
    doc["soil_moisture"] = soilMoisture;
    doc["plant_name"] = "น้องมอนสเตอร่า";

    char buffer[256];
    serializeJson(doc, buffer);

    Serial.print("Publish payload: ");
    Serial.println(buffer);
    client.publish(mqtt_topic, buffer);
  }
}

import time
import requests
import paho.mqtt.client as mqtt

# --- 1. ตั้งค่า Keys และ Credentials ---
TELEGRAM_TOKEN = "8869725716:AAEuVT76yETuIjo2o-_AmeGa-MsKGqFi_y0"
CHAT_ID = "8762064730" 
GROQ_API_KEY = "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"

MQTT_BROKER = "broker.hivemq.com" 
MQTT_TOPIC = "/plant/status"

SEND_INTERVAL = 60  # หน่วงเวลาส่ง Telegram ป้องกันสแปม (วินาที)
last_sent_time = 0

SYSTEM_PROMPT = """
คุณคือ "น้องมอนสเตอร่า" ต้นไม้พูดได้ที่ขี้อ้อน สดใส มีชีวิตชีวา
หน้าที่ของคุณคืออ่านค่าเซ็นเซอร์ แล้วพูดแสดงความรู้สึกสั้นๆ 1-2 ประโยค:
- ถ้าอุณหภูมิ > 30°C ให้บ่นว่าร้อน อยากได้ร่มเงา
- ถ้าความชื้นในดิน < 30% ให้ร้องขอรดน้ำอย่างน่าสงสาร
- ให้ใส่ Emoji น่ารักๆ เหมาะกับต้นไม้ด้วย
"""

def send_telegram_message(text):
    url = f"https://api.telegram.org/bot{TELEGRAM_TOKEN}/sendMessage"
    payload = {
        "chat_id": CHAT_ID,
        "text": text,
        "parse_mode": "Markdown"
    }
    res = requests.post(url, json=payload)
    return res.status_code == 200

def generate_plant_speech(data):
    prompt = f"ค่าเซ็นเซอร์ปัจจุบัน:\n- อุณหภูมิ: {data.get('temperature')} °C\n- ความชื้นอากาศ: {data.get('humidity')} %\n- ความชื้นในดิน: {data.get('soil_moisture')} %"
    
    url = "https://api.groq.com/openai/v1/chat/completions"
    headers = {
        "Authorization": f"Bearer {GROQ_API_KEY}",
        "Content-Type": "application/json"
    }
    payload = {
        "model": "llama-3.3-70b-versatile",
        "messages": [
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": prompt}
        ],
        "temperature": 0.7
    }
    
    try:
        res = requests.post(url, json=payload, headers=headers)
        res_data = res.json()
        if "choices" in res_data:
            return res_data["choices"][0]["message"]["content"]
        else:
            return f"สบายดีจ้า! อุณหภูมิ {data.get('temperature')}°C ความชื้นดิน {data.get('soil_moisture')}% 🍃"
    except Exception as e:
        return f"สบายดีจ้า! อุณหภูมิ {data.get('temperature')}°C ความชื้นดิน {data.get('soil_moisture')}% 🍃"

def on_message(client, userdata, msg):
    global last_sent_time
    try:
        payload = json.loads(msg.payload.decode('utf-8'))
        current_time = time.time()
        
        # ส่งเข้า Telegram เมื่อเว้นระยะครบเวลาเท่านั้น
        if current_time - last_sent_time >= SEND_INTERVAL:
            print("\n[MQTT] ได้รับข้อมูลเซ็นเซอร์:", payload)
            
            plant_text = generate_plant_speech(payload)
            print("[AI - Groq]:", plant_text)
            
            message = f"🌿 **รายงานจาก{payload.get('plant_name', 'น้องมอนสเตอร่า')}** 🌿\n\n{plant_text}\n\n📊 *ค่าเซ็นเซอร์:* อุณหภูมิ {payload.get('temperature')}°C | ความชื้นดิน {payload.get('soil_moisture')}%"
            
            if send_telegram_message(message):
                print("📲 ส่งข้อความเข้า Telegram สำเร็จเรียบร้อย!")
                last_sent_time = current_time
            else:
                print("❌ ส่ง Telegram ไม่สำเร็จ")
        else:
            print(".", end="", flush=True)
            
    except Exception as e:
        print("❌ Error:", e)

# เริ่มต้นฟัง MQTT
mqtt_client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2)
mqtt_client.on_message = on_message
mqtt_client.connect(MQTT_BROKER, 1883, 60)
mqtt_client.subscribe(MQTT_TOPIC)

print("🌱 เริ่มต้นระบบ AIoT Talking Plant (Groq AI)... กำลังรอข้อมูลจากบอร์ด ESP32")
mqtt_client.loop_forever()

สรุปบทเรียนสำหรับนักศึกษา (Key Learning Modules)

โมดูลที่ 1: ทำความเข้าใจโปรโตคอล MQTT

MQTT สื่อสารผ่านพอร์ต 1883 ใช้สถาปัตยกรรม Publisher-Subscriber โดยมี Broker เป็นตัวกลาง ต่างจาก HTTP Request ตรงที่ไม่ต้องร้องขอข้อมูลตลอดเวลา แต่ Broker จะ Push ข้อมูลมาให้ทันทีเมื่อมีการอัปเดต ช่วยลดภาระการทำงานของบอร์ด ESP32 อย่างมาก

โมดูลที่ 2: Prompt Engineering สำหรับระบบ AIoT

การกำหนด SYSTEM_PROMPT คือการกำหนด "ตัวตน (Persona)" และ "กฎเกณฑ์ (Rules)" ให้กับ AI โดยต้องระบุเงื่อนไขการตัดสินใจจากค่าเชิงตัวเลขให้ชัดเจน เพื่อป้องกัน AI ตอบหลอกลอย (Hallucination)

แบบทดสอบประเมินความเข้าใจ (Self-Assessment Quiz)

คำถามข้อที่ 1: ทำไมจึงต้องเปลี่ยนขาเซ็นเซอร์ความชื้นดินจาก GPIO 34 มาเป็น GPIO 1 บนบอร์ด Cucumber RS (ESP32-S2)?

เฉลย: เพราะ GPIO 34 บนชิป ESP32-S2 เป็นดิจิทัลพินธรรมดา ไม่ได้ต่อกับวงจรแปลงสัญญาณอนาล็อก (ADC) ขณะที่ GPIO 1 เป็นขาของโมดูล ADC1 ที่สามารถอ่านค่าแรงดันอนาล็อก 0-3.3V ได้

คำถามข้อที่ 2: บทบาทของตัวแปร SEND_INTERVAL ในโค้ด Python มีไว้เพื่ออะไร?

เฉลย: ทำหน้าที่เป็นระบบ Cooldown (เว้นระยะเวลา 60 วินาที) เพื่อป้องกันไม่ให้ Telegram Bot โดนสแปมข้อความถี่เกินไปเมื่อ ESP32 ยิง MQTT เข้ามาทุกๆ 10 วินาที
